APPROACH

이런 방식으로 일합니다

기능을 만드는 것만큼, 기능이 틀어졌을 때 어떻게 되는지를 먼저 생각합니다.

1

규칙을 먼저 적고, DB가 지키게 합니다

"한 좌석은 한 시간에 한 명"처럼 깨지면 안 되는 규칙부터 정합니다. 코드에서 확인하면 동시에 온 요청이 같은 확인을 통과하므로, 마지막 방어선은 DB 제약으로 둡니다.

UNIQUE(seat_id, slot_start)
2

덮어쓰지 않고 쌓아 둡니다

포인트 잔액을 고치는 대신 충전·사용·환불을 원장에 차례로 남기고, 잔액은 합계로 구합니다. 같은 예약의 환불이 두 번 기록되지 않도록 제약도 걸어 두었습니다.

UNIQUE(예약, 사유)
3

확인한 것과 못 한 것을 나눠 적습니다

자동 시험을 돌린 범위와 아직 못 해 본 범위를 문서에 함께 적습니다. 예를 들어 StudySeat는 H2에서 시험했고 MySQL 8 실서버 검증은 남아 있다고 밝혀 둡니다.

StudySeat

전국 지도에서 지점을 찾고 도면에서 좌석을 눌러 예약하는 스터디카페 서비스

문제

같은 좌석에 여러 요청이 동시에 오면 둘 다 "비어 있다"고 확인하고 예약될 수 있습니다. 포인트도 겹친 요청에 두 번 빠질 수 있습니다.

해결

예약을 1시간 슬롯 행으로 나눠 유니크 제약을 걸고, 포인트는 원장에 쌓으며 회원 행에 락을 걸어 순서대로 처리했습니다. 좌석 수만 주면 도면을 배치하는 엔진도 만들었습니다.

결과

20명이 동시에 예약해도 1명만 성공합니다. 자동 시험 40개와 도면 756개 조합 시험을 통과했습니다.

Java 17Spring BootJPAFlywayThymeleaf
